> 本文为业务需求基线；当前结构和运行方式见项目 README。
>
> 前端目录：`frontend/`
>
> 文档版本：v1.1（2026-10-08）
>
> 适用人员：小程序前端、管理后台前端、后端联调人员

## 1. 文档目的和交付边界

### 2026-10-08 确认：负责人分工与数据查看范围

**管理后台从阶段 0 开始就是必交付工程，与小程序同步开发。** 前端负责人负责 `frontend/miniprogram/`、`frontend/admin/`、`frontend/shared/` 和 `frontend/assets/`：所有小程序/后台页面、路由、组件、交互、接口请求、类型、模拟数据和构建。后端负责人负责 Java 接口、数据库、业务校验、指标聚合与渠道适配，不代做管理后台页面。

已确定：自建后台查看订单、销售额、退款、会员、分销佣金和提现；访问人数、访问次数、新访问用户等基础数据由运营在微信公众平台查看。首期不做微信小店对接、不做微信访问统计同步、不新增访客采集 SDK。前端不增加微信小店菜单、访客卡片或同步按钮；开发 mock 必须标记为开发数据，联调后切换真实业务 API。

接口未实现时按共享契约和同格式 fixtures 开发，不需要等待后端全部完成。只修改前端负责目录，不直接改数据库或后端业务规则；共享契约字段变更按《接口契约与联调约定》第 12 节交接。后台与小程序都由前端负责界面验收，后端负责接口行为验收，阶段结束共同验收业务链路。

配套阅读：[交付与阶段总览](README.md)、[共享接口契约](接口契约与联调约定.md)、[后端业务规则](后端开发需求文档.md)。本文第 3、4、10 章指导页面设计，第 7 章安排实施阶段。

本文件用于指导一名前端开发者同时完成：

1. 面向顾客的微信小程序（uni-app）。
2. 面向运营人员的 Web 管理后台（Vue 3 + Vite + Element Plus）。
3. 两端共用的请求层、类型、枚举、格式化方法和联调约定。

参考商城只用于提取页面结构、视觉节奏和必要交互，不复制品牌、文案、价格、二维码、联系方式或平台代码。旧调研图库已清理；当前可维护设计源保存在 frontend/assets/design/lishan-v1。

本项目必须实现客户已经确认的业务范围：

- 视频课程：录播、多章节、单独购买，后台设置购买后的观看有效期；会员试卷不自动包含付费视频课程。
- 自有实体书：在线下单、收货地址、库存、后台填写运单号、用户查询物流进度。
- 试卷会员：一个会员等级，半年/一年套餐；有效期内下载全部会员试卷；支持 Word、PDF、图片；续费从原到期时间顺延。
- 首页装修：顶部搜索、三张轮播图、八个快捷入口、可增删/排序的内容模块。
- 一级分销：每个商品可指定一个或多个分销员和佣金比例；分享链接/小程序码归因；满足结算条件后可线上自动提现。
- 后台经营数据：订单、销售额、退款、商品、会员和分销数据可查看。

首页和详情页要覆盖加载中、空数据、错误、下架、登录失效、无权限、网络重试等状态。本文为需求设计，页面尚未实现。前端不以“隐藏按钮”代替权限控制，所有购买、播放、预览、下载和提现动作都必须由后端再次校验。

## 2. 固定技术和工程结构

### 2.1 技术栈

| 端 | 固定技术 |
|---|---|
| 微信小程序 | uni-app、Vue 3、TypeScript、Pinia、SCSS |
| 管理后台 | Vue 3、TypeScript、Vite、Element Plus |
| 请求 | `uni.request` 封装；后台使用同一套请求约定 |
| 类型 | TypeScript，接口 DTO 与后端 OpenAPI/契约同步 |
| 构建 | npm；小程序通过 HBuilderX 或官方 CLI 构建，后台使用 Vite |
| 代码质量 | ESLint、Prettier、TypeScript `noImplicitAny`；提交前类型检查 |

`wechat-fhdj` 是原生微信小程序，不能把它的 WXML/WXSS 当作本项目代码；可以参考其中的类型化请求、环境配置和状态映射思路，但本项目继续使用已确定的 uni-app 方案。

### 2.2 建议目录

```text
frontend/
├─ miniprogram/                 # uni-app 小程序工程
│  ├─ src/
│  │  ├─ pages/                 # 页面
│  │  ├─ components/            # 业务组件
│  │  ├─ composables/           # 可复用组合式逻辑
│  │  ├─ stores/                # Pinia：用户、订单草稿、配置
│  │  ├─ api/                   # 领域 API 和请求封装
│  │  ├─ types/                 # DTO、枚举、视图模型
│  │  ├─ utils/                 # 金额、时间、文件、错误处理
│  │  ├─ static/                # 经过压缩、实际用于构建的少量素材
│  │  ├─ pages.json
│  │  ├─ manifest.json
│  │  └─ App.vue
│  └─ package.json
├─ admin/                       # Vue 3 + Vite + Element Plus
│  ├─ src/
│  │  ├─ views/                 # 运营页面
│  │  ├─ components/
│  │  ├─ layouts/
│  │  ├─ router/
│  │  ├─ stores/
│  │  ├─ api/
│  │  ├─ types/
│  │  └─ assets/
│  └─ package.json
├─ assets/                      # 参考素材库，不直接整体打包
└─ shared/                      # 可选：两端共用的契约类型与常量
```

如果采用 monorepo，可将 `shared/` 配置为 workspace 包；如果两个工程独立构建，则以 `docs/接口契约与联调约定.md` 为准，变更必须同时修改两端类型。

### 2.3 环境

至少提供 `dev`、`test`、`prod` 三套配置：

- API 基地址、上传地址、图片域名、视频域名、日志开关分开配置。
- `dev` 和早期 `test` 使用开发登录/支付/转账适配器；阶段 5 单独配置真实联调环境，显式选择 Provider；`prod` 禁止模拟能力，不自动回退。
- AppID 是客户端必要标识，可作为构建配置；AppSecret、商户私钥、API v3 密钥、对象存储密钥不得进入前端包或 Git。示例文件只写占位值。
- 前端展示金额统一由后端返回的 `amountFen` 格式化为元；不要用浮点数计算金额。

## 3. 视觉设计和组件规范

### 3.1 视觉方向

设计主题是“语文教学资料商城”：内容密度适中、阅读优先、购买动作清晰。保留参考站的浅灰页面底、白色卡片、顶部横幅、两行四列快捷入口、双列商品卡和固定底部导航；用本项目自己的品牌文案和素材替换原站内容。

参考实测值（视口约 422px，仅作为比例依据）：

| token | 值/建议 |
|---|---|
| 页面底色 | `#F5F7FA` |
| 卡片 | `#FFFFFF`，圆角 `9px` 左右 |
| 主文字 | `#333333` |
| 次文字 | `#8A8F98` |
| 价格 | `#FF5024` |
| 主要操作 | 初始建议 `#2F80ED`；品牌确认后集中替换 |
| 快捷入口强调色 | 初始建议清爽绿色 `#2DBE5C` |
| 内容宽度 | 页面左右边距 12px；卡片间距 8px |
| 商品封面 | 约 4:3，使用 `aspect-ratio` 或等价占位方案 |
| 标题 | 15–16px、600、最多两行省略 |
| 正文 | 14px；行高约 1.6 |
| 点击区域 | 交互控件最小约 44×44px |

颜色 token 集中放在 `styles/tokens.scss`，不要在页面中散落硬编码。价格、库存不足、已过期、退款等语义色在小程序和后台保持一致。

### 3.2 公共组件

必须先抽成组件，再在页面重复使用：

- `AppSearchBar`：搜索图标、输入、清空、提交、历史关键词（历史可后置）。
- `HomeCarousel`：三张后台配置图片，支持跳商品/课程/会员/图文/试卷列表；图片失败显示占位。首期不提供任意外部 URL 跳转。
- `ShortcutGrid`：八个入口，图标、名称、目标类型由后台返回；未配置的入口不占位或按后台策略隐藏。
- `HomeSection`：标题、查看更多、商品/内容列表、排序；支持后台显示隐藏和顺序。
- `ProductCard`：封面、商品类型、标题、现价、划线价、有效期/会员标签、库存提示。
- `ProductListItem`：列表页左图右文，支持分页和触底加载。
- `PriceText`：接受整数分，统一处理免费、原价、活动价，禁止组件内部做浮点运算。
- `FileRow`：文件名、扩展名、大小、预览/下载按钮和权限状态。
- `OrderStatusBadge`、`MembershipBadge`、`CommissionStatusBadge`。
- `EmptyState`、`ErrorState`、`SkeletonCard`、`LoginRequired`、`PermissionDenied`。
- `BottomTabBar`：首页、学习/课程、订单、我的；分销入口从我的或商品分享进入，不额外挤占底部栏。

### 3.3 素材规则

`frontend/assets/design/lishan-v1/` 是现行设计素材源。开发者需要：

1. 先从 `manifest.json` 查来源和用途，再挑选可合法使用的公共视觉元素。
2. 将实际使用的图片压缩、改名、去除原站品牌/二维码/联系方式后放入 `miniprogram/src/static/`。
3. 商品封面、轮播图、课程详情图和试卷文件由后台上传，生产环境返回对象存储 URL；不要将所有商品资源打进包体。
4. SVG 在微信真机验证；不兼容时导出同尺寸 PNG。图标不能依赖参考站远程域名。
5. 每个正式资源记录业务用途和版权来源；原站编译 JS、CSS、WASM 不导入执行。

## 4. 小程序页面需求

下面的路由名称是建议稳定标识；实际 uni-app 路由可按工程习惯调整，但页面职责、数据和状态不能减少。

### 4.1 首页 `/pages/home/index`

布局顺序：搜索框 → 三图轮播 → 八入口网格 → 可排序内容模块 → 固定底部导航。

- 首屏请求首页装修配置和商品摘要；轮播、快捷入口和区块全部以后端排序为准。
- 每个模块显示标题和“查看更多”；模块类型至少支持商品楼层、课程楼层、会员入口、图文入口。
- 商品双列卡片显示封面、标题、类型、现价/划线价；点击进入详情。
- 加载时使用骨架屏；无内容时显示“暂无内容”，不要留大面积空白；接口失败显示重试。
- 搜索框提交到搜索页；快捷入口按 `targetType` 跳转，不根据名称硬编码。
- 用户未登录仍可浏览公开首页；点击购买、加入学习、学习中心或我的中的受保护内容时进入登录流程。

验收：后台拖动区块顺序、上下架轮播或修改快捷入口后，重新进入首页能看到对应结果；接口返回的模块顺序不被前端重新排序。

### 4.2 搜索 `/pages/search/index`

- 支持关键词、商品类型筛选（课程/图书/会员/试卷资料）、综合/价格/最新排序。
- 结果分页，避免一次加载全部商品；搜索无结果显示关键词和清空筛选操作。
- 进入页面时保留最近一次关键词；提交空关键词时提示，不请求全量接口。
- 商品卡片与首页使用同一 `ProductCard`，详情跳转保持 `productId`。

### 4.3 商品列表与详情

商品列表 `/pages/product/list`：支持分类、类型、上下架过滤后的公开结果、分页和触底加载。实体书需要显示库存或“补货中”；课程显示观看有效期；会员显示半年/一年套餐入口。

详情 `/pages/product/detail`：

- 顶部封面、商品类型、标题、现价、原价、介绍摘要。
- 课程：有效期说明、章节数、试看章节/样张、课程图文详情；购买后显示“开始学习”。
- 图书：规格/数量、库存、图文详情、配送说明；库存不足时禁止提交订单。
- 会员：半年/一年计划卡片、权益说明、当前会员到期日；已购买且未到期时显示续费提示。
- 试卷资料：分类、文件格式和会员权限提示；会员商品不显示为普通视频课程。
- 会员试卷文件只显示文件名和权限状态，预览与下载均校验会员；课程提供章节和公开样张，首期不另售试卷包，不把会员试卷混入单独购买的课程权益。
- 底部操作按类型显示：`立即购买`、`开始学习`、`下载/查看会员资料`、`分享`。下架商品只允许查看，不允许购买。

### 4.4 课程与学习

课程学习 `/pages/course/learn`：

- 显示课程名称、当前章节、章节列表、已学进度和有效期截止时间。
- 播放 URL 必须由后端按 `courseId/chapterId` 授权后返回，前端不保存永久公开地址。
- 章节支持锁定、试看、已完成、播放失败；切换章节前保存播放进度，采用防抖。
- 有效期结束显示到期页和重新购买入口；会员状态不能解锁单独付费课程。
- 视频组件要处理网络中断、暂停、全屏、播放完成；播放完成向后端提交学习记录，重复提交不造成重复数据。

我的课程 `/pages/learning/courses`：按“学习中/已完成/已过期”展示已购课程，支持继续学习。

### 4.5 会员试卷

会员中心 `/pages/membership/index`：

- 未开通：展示半年、一年计划、价格、权益和购买按钮。
- 已开通：展示当前等级、开始时间、到期时间、续费按钮；续费文案明确“从当前到期日顺延”。
- 已过期：仍展示历史权益和重新开通按钮；下载按钮变为“会员已过期”。

试卷列表 `/pages/paper/index`：按年级、学段、年份、科目筛选；显示文件类型（Word/PDF/图片）、大小和下载权限。有效会员可以下载全部会员试卷，不在前端设置次数上限；后端仍记录每次访问用于审计。

下载交互：点击预览/下载 → 请求一次性或短时效授权 URL → 用 `uni.downloadFile` 或受支持的预览能力打开 → 失败允许重新获取授权。不得把永久 URL 写入页面参数、日志或剪贴板。

### 4.6 图书、地址和物流

- 地址页 `/pages/address/list`、`/pages/address/edit`：收件人、手机号、地区、详细地址、默认地址；手机号和必填项前端校验，后端再次校验。
- 确认订单 `/pages/order/confirm`：展示商品、数量、价格、运费、收货地址、应付金额；金额以预览接口返回为准，提交前重新获取订单预览。
- 物流页 `/pages/order/logistics`：订单状态、快递公司、运单号、物流轨迹时间线；无轨迹时显示“商家已发货，物流信息同步中”。
- 商家未填写运单号时，用户看到“待发货”，不能显示伪造物流。
- 数量步进器、库存锁定失败、地址失效、价格变更都要给出明确提示并允许回到确认页刷新。

### 4.7 订单、售后和我的

订单 `/pages/order/list`：全部、待付款、待发货、运输中、已完成、售后/退款筛选；分页加载。订单详情显示订单快照、支付状态、权益状态、收货信息、物流、售后记录。

- 待付款允许取消；超时由后端关闭，前端回到页面时刷新状态。
- 付款按钮先创建/获取支付参数，再调用微信支付；支付结果以服务端查询/回调为准，前端只展示处理中并轮询有限次数。
- 实体书支持申请售后；课程/会员/文件是否可退以商品和订单规则返回，前端展示后端原因。
- 退款中、退款成功、退款失败都要显示原因和下一步，不允许前端自行把订单改成退款成功。

我的 `/pages/profile/index`：用户信息、订单、我的课程、会员、地址、分销中心、设置。公开浏览不强制登录；进入账户数据页时再触发登录。

### 4.8 分销和自动提现

分销中心 `/pages/distribution/index`：待结算、可提现、提现中、累计已提现、提现记录和规则说明；不得把待结算佣金和提现中资金合成无法分辨的冻结中。佣金明细显示商品、订单号脱敏、金额、状态和预计可提现时间。

- 商品详情的分享按钮调用后端获取分享参数/小程序码，分享内容只带短 token，不暴露用户手机号或内部 ID。
- 分销员由后台指定已注册用户；无分销档案时隐藏分销入口，深链进入返回无权限；已停用分销员保留历史佣金与提现入口，风险冻结单独限制提现。首期不开发分销招募或申请页面。
- 申请提现时前端展示最低金额、可提现余额、预计到账说明和实名/微信收款提示；具体阈值由后端配置返回。
- 提现提交后显示“处理中”，禁止重复点击；成功、失败、需要用户确认、已关闭分别展示。
- 微信商家转账未开通时，生产环境不显示“已到账”或伪造成功，只显示服务暂不可用并保留申请状态。

## 5. 管理后台页面需求

后台使用左侧菜单、顶部当前用户/环境标识、面包屑和内容区。业务记录列表支持分页、筛选和适用的排序；订单/佣金/提现/统计按权限导出，字典和装修不要求导出；所有写操作显示成功/失败提示并记录操作日志。

### 5.1 菜单和页面

| 菜单 | 页面和职责 |
|---|---|

### 5.2 表单和交互要求

- 金额输入显示“元”，提交转换为分；佣金输入百分比并显示有效范围，保存后提示会影响新订单还是立即生效。
- 商品编辑按交付类型分步骤显示字段，课程不出现库存/快递字段，实体书不出现播放字段。
- 上传先获取后端上传凭证，再上传到对象存储，最后提交文件元数据；上传失败可重试，未完成的临时文件可清理。
- 删除内容优先软删除/下架；已有订单引用的商品不得物理删除。
- 拖拽排序后保存明确提示“排序已保存”；并发编辑失败时要求刷新，不覆盖他人修改。
- 发货填写运单号前显示订单收货摘要；修改运单号需原因并写审计日志。
- 佣金提现状态只能由后端转账结果驱动；管理员不能在前端把失败改为成功。

### 管理后台经营数据的实现要求

工作台使用 `/admin/analytics/overview`、`/admin/analytics/trend`，具体字段见共享契约第 13 节；前端负责日期筛选、卡片/趋势、加载/空态/失败重试、权限展示。不得拉取全量订单在浏览器求和，不把支付成功或提现到账状态由前端自行推导。

| 界面 | 展示要求 |
|---|---|

日期统一 Asia/Shanghai；无业务数据展示0/空趋势，接口失败展示错误，不回填演示数字。权限不足隐藏敏感菜单，服务端仍需鉴权。

后台阶段安排：阶段0完成工程、登录页、布局和权限状态；阶段1完成装修/商品内容；阶段2订单/发货；阶段3课程/会员/试卷；阶段4经营数据/分销/提现；阶段5真实渠道联调。后台从一开始存在，统计页面随业务数据成熟在阶段4验收。

前端验收补充：小程序与后台可分别启动；未实现接口可用同格式fixtures；后台业务卡片使用真实接口后值与后端一致；生产构建没有微信小店连接、访客采集或假收入。页面具备加载、空数据、失败和无权限状态。

### 6.1 登录

阶段 1–4 使用开发登录适配器，仅限 `dev/test`。登录态由 Pinia 管理，token 放在 uni-app 合适的本地存储中，退出时清除用户缓存和短期授权 URL。真实 AppID 登录放到最后阶段：前端调用 `wx.login`（由 uni-app 平台 API 封装），服务端换取用户身份；不在前端保存 `AppSecret`。

登录失效（401）统一清理登录态并跳转登录页，保留原目标路由一次；取消登录返回原页面，不循环跳转。

### 6.2 请求和响应

请求层统一处理：超时、网络失败、401、403、业务错误码、分页、请求 ID 和幂等键。金额使用 `amountFen`，时间使用 ISO-8601 带时区字符串，分页使用 `items/page/pageSize/total`。接口示例和状态枚举见 `docs/接口契约与联调约定.md`。

重要写操作由前端生成 UUID 作为 Idempotency-Key，按业务动作保存至结果确定，重试复用原值。按钮点击后立即禁用；超时使用请求结果查询接口，不重新生成键再提交。同键不同请求体返回冲突，须核对原业务，不能覆盖旧请求。

### 6.3 文件和媒体

所有课程播放、会员文件预览/下载、后台上传均经过后端授权。短链过期、文件被禁用、权限变化时显示可行动的提示。日志只记录 asset ID 和结果，不记录完整签名 URL。

## 9. 上线前置条件

自动提现不是纯前端功能。微信官方商家转账支持“佣金报酬”场景，但商户需要在商户平台申请开通、配置安全 IP、资金和转账场景，并接入查询/回调。当前已知“有主体和商户号，但商家转账能力尚未开通或不清楚”，因此阶段 5 的上线检查必须包含：

1. 确认商户不是不支持的商户类型，完成商家转账权限申请。
2. 确认佣金报酬场景、收款模式、额度、实名校验和用户授权流程。
3. 完成正式证书、API 密钥、回调域名、安全 IP 和资金充值配置。
4. 使用小额测试单验证成功、用户未收款、失败、查询和重试，不把“接口请求成功”当作到账成功。

这些是环境和资质前置条件，不能用前端假成功替代。

| USER_ACTION_REQUIRED | 请确认收款；按钮“去微信确认” | 用支付API冒充收款确认；关闭弹窗就显示失败 |
| SUCCEEDED | 已到账；显示金额和到账时间 | 仅凭前端回调切换成功 |
| FAILED/CLOSED | 显示渠道解释及最终余额；可重新申请 | 原单未终态时重发 |

首期自动是系统处理和出款，不代表绕过微信收款确认。后端返回 confirmation.action/payload；前端用微信当期官方支持的收款组件/接口拉起，平台能力缺失要明确提示并保留查单入口。正式商家转账未开通是上线依赖，不能换成人工“标记成功”。

### 10.5 预览、下载、登录与分享实现

- Word/PDF：授权→downloadFile→openDocument；格式支持与文件大小限制在 iOS/Android 真机检查，失败显示原因/重试。明确提供系统支持的保存/分享入口，不能把“打开预览”当作所有下载需求已满足。
- 图片：授权后 previewImage；用户点击保存才请求相册授权并调用保存能力。拒绝授权后仍可预览，不无限弹权限框。文件名过长两行截断，扩展名和大小独立显示。
- session：随机不透明 Bearer token。小程序登录态保存在受控 storage，日志不输出；后台首期 token 保存在内存+sessionStorage，退出清除，配合服务端撤销和超时。管理员登录使用安全哈希验证和限流。
- 分享：页面收到scene/referralCode→resolve→缓存服务端 attributionToken→登录后关联→同商品下单传token；不通过URL自行声明佣金比例。分享按钮只出现于可推广商品，不把普通购买者变成分销员。小程序码由后端生成，正式二维码放阶段5；前期用开发短码模拟跳转。

### 10.6 管理后台表单细节

后台建议最小宽度1280px，侧栏208px，页头56px，内容区24px间距；Element Plus默认简洁风格，表格主操作固定右侧。订单和财务页权限由后台返回的 permissions 决定菜单可见性，服务端再次校验。

| 页面 | 必填项/校验 | 保存/发布行为 |
|---|---|---|
| 首页装修 | 轮播图+内部目标；8入口名称/图标/目标；模块类型/标题/商品 | 草稿、预览、发布三步；revision并发校验；发布前校验3/8数量 |
| 商品 | 类型、标题1–100字、价格>=0.01元、封面、介绍、分类 | 创建草稿，字段齐全才上架；原价>=现价；类型售出后不可修改 |
| 课程 | 有效期DAYS/PERMANENT，DAYS正整数；章节标题、视频、顺序、试看开关 | 上传未READY章节不能发布；修改有效期仅影响新订单，明确提示 |
| 图书 | 初始库存、配送地区、每单运费/包邮规则 | 调整库存填入库/盘点原因，不能直接覆盖已占用库存 |
| 会员套餐 | 半年/一年、售价、说明 | 周期6/12个月；已有订单周期快照不变；每周期启用一个计划 |
| 试卷 | 标题、学段/年级/科目、可选年份、至少一文件 | 文件扩展名/MIME/大小校验，Word/PDF/图片均支持；原文不公开 |
| 订单售后 | 原因、商品退款额、运费退款额；图书退货入库数量 | 展示剩余可退额与会员/课程/佣金影响预览，权限操作才可批准 |
| 发货 | 快递编码、运单号、收货摘要核对 | 幂等提交；修改运单填原因；不得复制参考站微信发地址流程 |
| 分销配置 | 已注册分销员、商品、比例0–100%最多两位小数 | 同商品多人分别配置，不表示一单多人分佣；影响新订单 |
| 提现对账 | 只读状态/渠道单号/失败原因/金额 | 可重新查单，不可编辑到账状态；默认不设人工逐笔审批 |
| 经营数据 | 日期区间、商品类型 | 实收、退款、净额、销量、会员、佣金分列；净额不命名为利润 |
