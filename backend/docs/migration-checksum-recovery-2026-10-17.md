# 本地重启 V22/V23 校验冲突修复

## 原因与恢复策略

IDEA 使用 dev,local 启动时，Flyway 报 V22、V23 checksum mismatch。数据库已执行中间版本，随后源文件被修改；空库隔离测试不能覆盖这一已执行版本路径。

从本轮实际补丁记录恢复原始 SQL，V22 校验值为 `-983193997`，V23 为 `-429532284`，与用户启动日志的 Applied to database 一致。保留历史重复索引，避免再次修改已执行 V22。后续索引与触发器修正移入 V25，不调用 repair，不关闭校验，不删除迁移历史或业务数据。

V25 补上首次发布时间索引、INSERT 触发器，并替换 UPDATE 触发器以兼容旧版直接 INSERT 已发布内容的空时间；此类旧记录按 created_at 回填，已存在的非空首次发布时间保留。回填不增加业务 version、不重发首页。

本修复适配用户日志中上述两个已执行 checksum。其他环境如执行了另一种中间版本，应先核对迁移历史与实际结构，不可盲目 repair。

## 使用

重新编译资源后，以原 IDEA `dev,local` 配置重启即可；Flyway 校验恢复后的 V22/V23，再正常执行 V25。不需要修改账号、连接配置或运行清库命令。

## 维护约束

升级行为由 MigrationTest 的已应用版本兼容测试覆盖。源码整理不运行 repair、不修改历史迁移或业务数据库。不要使用旧交付包的哈希判断新构建；每次发布重新构建并核对产物。
